# 0021. Adoptar monorepo incremental para outer harnesses

Reemplaza a 0011-consolidar-configuracion-y-runtime-en-a4s.

## Contexto
A4S ahora reúne capacidades incrementales para developers multi-repo y la decisión de no crear un monorepo de proyectos relacionados ya no describe su dirección.

## Decisión
A4S convierte trabajo multi-repo recurrente en capacidades incrementales para outer harnesses; las piezas sólo entran en la narrativa cuando son usables y las integraciones no definen su categoría.

## Alternativas descartadas
Mantener la narrativa de producto único: contradice la dirección aprobada; definir A4S por un runtime propio o una integración concreta: contradice los límites aprobados; prometer una suite, universalidad o autonomía: excede la evidencia actual.

## Consecuencias
La decisión 0011 queda superseded; README y documentación viva deberán separar capacidades, paquetes e integraciones sin reescribir registros históricos.
