# Empirical Capability Development

- **Owner:** A4S.
- **Contribution:** portable, opt-in capability discovery before fresh product work.
- **Verification:** the result and cleanup are recorded; no automatic enforcement is claimed.
- **Portability:** runtime-neutral; each repository binds the method through its own rules.

**Entry:** a material `UNKNOWN` blocks a decision and a safe disposable probe exists.

1. Write one question.
2. Run the smallest native probe.
3. Read the effect independently.
4. Classify the result: `demonstrated`, `refuted`, or `inconclusive`.
5. Preserve the finding and verify cleanup.

**Guardrails:**

- No shared or production target.
- Never promote spike code into product code.
- No unrelated work.

**Stop:** the result and cleanup are recorded.

- If `demonstrated`, start fresh product work from the finding.
- If `refuted`, close the work.
- If `inconclusive`, block only the dependent path.
